How this log is kept current

  1. After each batch or incident: add an incident card (symptom → root cause → fix → lesson), update the ledger, stats, and the Last updated stamp.
  2. Numbers come from the tools, never from memory: tickets/runs from factory.db, PRs from gh pr list --state all, commits from git log.

Incident log — what broke and what it taught us

Every entry is a real failure from a real run, in the order it was hit. This is the most valuable section of the repo.

Sandbox & security

S1 · The agent could read your tokens and write outside the worktree sandbox

Symptom run_command was the one shell surface — and it inherited the full environment (GitHub token included) and allowed shell redirection to any path on disk.

Root cause Default-trust subprocess: subprocess.run(shell=True) with no env filtering; deny-list covered commands, not redirection.

Fix Allowlisted environment (PR #6) — the agent gets PATH and nothing else; redirection outside the worktree refused; path guards resolve every path and reject escapes and .git.

Lesson An agent's environment is part of the blast radius. Default-deny env, then add what's proven needed.

S2 · The human gate was silently dead sandbox

Symptom Every change rated low blast radius, so nothing ever needed David's approval — including changes to the gates themselves.

Root cause Blast radius was computed from the diff after the worker's commit, so the diff was always empty.

Fix Capture the base SHA before committing and classify against it. Caught by tests/smoke.py — the smoke test earned its keep on day one.

Lesson A security control that fails silently is worse than none. Test gates against a change that must trip them.

S3 · Secret scanner flagged the whole checkout sandbox

Symptom Runs blocked on "secrets" that were already in the repo (test fixtures, docs).

Fix Scan only the lines a change adds, not the whole tree.

S4 · The factory ran with your whole GitHub account sandbox

Symptom Pushes used the ambient gh credential — full account scope for a bot that only needs to push agent/* branches and open PRs on one repo.

Fix Fine-grained scoped credential (PR #4), proven with live permission/scope probes before trusting it. Worker uses it, not your login.

S5 · A "tests" PR passed CI with zero tests — and shipped Windows system binaries sandbox

Symptom PR #37 (ticket 13) merged-clean on all checks. Diff: one scratch file and six Windows system-cache binaries — the agent had written to a literal %SystemDrive%\... path inside the worktree and committed whatever landed.

Root cause Gates checked "tests pass" and "no secrets" — nothing checked that a test ticket produced tests, or that the diff was text.

Fix Junk gate in the worker: reject any diff containing binary files; reject a test-ticket whose diff touches no file under tests/. Both fail the attempt, so the ticket retries instead of dying.

Lesson Green CI ≠ correct change. Gates must assert the ticket's intent, not just hygiene.

Pipeline correctness

P1 · Failed pushes reported success pipeline

Symptom Tickets went pr_open with no clickable PR — one even with no PR at all.

Fix Verify push and PR-creation results explicitly; a ticket is not pr_open until a human can click a link.

P2 · Everything worked — on my machine pipeline

Symptom First Linux CI run caught three bugs the Windows dev loop never saw (path handling, encodings).

Fix CI matrix runs the suite on Linux and Windows on every PR, forever after.

P3 · git commit refused our own pathspec pipeline

Symptom commit_all died: git rejects exclude pathspecs (

Fix Stage explicitly instead of exclude-pathspecs; regression test added.

P4 · One stale worktree poisoned every later run pipeline

Symptom After one crashed run, every subsequent run failed on the same leftover branch/worktree.

Fix Worker prunes stale worktrees and clears its own old branches before starting (agent-only branch guard — it may never touch human branches).

P5 · A batch ran the old runner pipeline

Symptom Fixes were merged and pushed, but the next batch behaved like pre-fix code.

Root cause The batch executed the working tree, and local main lagged origin/main.

Fix Every batch pins origin/main and greps the runner for a known marker before launching — refuse to run code you can't prove is current.

P6 · Runs died at the same step number, every time pipeline

Symptom Hard stop at a fixed step regardless of task size.

Root cause The token governor capped cumulative tokens across the whole loop instead of the context window — but every step resends the whole conversation, so the real wall is per-request context.

Fix Governor measures the next request's projected context, not the sum of all usage.

Lesson With chat-loop LLMs, "tokens used" and "tokens in context" are different quantities. Budget the second one.

P7 · The agent could declare victory with an empty diff pipeline

Symptom Runs ended completed with a confident summary and zero changed files.

Fix Judge runs by the diff and the gates, not by finish() (PR #10). A summary is a claim; the diff is the fact.

P8 · Tier router used facts that didn't exist yet pipeline

Symptom Escalation decisions referenced attempt history/blast data only available after routing.

Fix Route only on inputs that exist at routing time (PR #7); escalation happens between attempts, not inside one.

P9–P11 · The factory fixed its own bugs pipeline

Tickets 9 and 10 were real factory bugs filed as tickets, and the agent shipped the fixes: daily budget reset at UTC instead of local midnight (PR #17), and retries dying pushing to a stale remote branch (PR #18, with a test that proves retry clears the stale branch against a real bare git origin). Also: sync now reopens a ticket when its PR is reopened (PR #15), and transient git failures outside the pipeline are retried instead of escalated.

P12 · The pasted PAT died mid-build pipeline

Symptom Phase 2's first live tick: every GitHub call 401'd. The ghp_ token in factory.json had been revoked server-side — pasted tokens age out and die silently until the next unattended run discovers it at 3 a.m.

Root cause Two sources of GitHub identity: the gh CLI keyring login (alive, refreshing) and a hand-copied PAT in config (dead). The factory trusted the dead one.

Fix One credential: the scheduler wrapper resolves gh auth token at runtime; factory.json carries env:FACTORY_GH_TOKEN, never a secret. A missing variable expands to empty string so gh falls back to its keyring login and failures stay loud.

Lesson Unattended systems must authenticate through the one identity that can renew itself. A pasted secret is a scheduled outage.

Agent behavior

A1 · Six tickets, six attempts each, zero write calls agent

Symptom All "write tests for X" tickets died at ~24 steps having only read and searched. Transcripts showed perfect analysis, no edits.

Root cause Tool design: the only write tools were write_file (rewrite the entire 1,300-line test file — too big to emit) and edit_file (needs a perfect anchor). No append. The model chose endless exploration over an impossible write.

Fix Added append_file + a system-prompt rule: "To add a test class to a large existing file, use append_file; never rewrite a large file, and never keep exploring instead of editing." The same tickets then shipped on the first attempt.

Lesson What looks like model failure is often tool-design failure. Check what the agent was able to do before blaming what it "chose" to do.

A2 · The board looked empty (404) agent

Symptom Board URL returned 404 to an anonymous fetch; suspected empty project.

Root cause Personal GitHub Projects are private by default — 404 to logged-out fetchers. The repo was public; the board had 15 items all along. Not a bug: an auth wall wearing a 404 costume.

Ticket specs — the real ceiling

T1 · Eight failed attempts, and the bug was in the ticket spec

Symptom Ticket 13 ("tests for local-midnight spend_today") failed 8 attempts / $1.37 while other tickets shipped for pennies.

Root cause The ticket body told the agent to fake time.localtime/struct_time/gmtoff — while the function under test takes an injectable epoch float. The spec pushed the model into the one corner where a 4B-class model can't dance.

Fix Closed 13; split into tickets 16/17 with explicit class names, the seam named ("pass now=; do NOT patch time"), and "use append_file". Both shipped first try, $0.06 and $0.09.

Lesson Ticket quality dominates model quality. Name the seam, forbid the trap, size the ticket to the tier.

T2 · A ticket with no passing solution spec

Symptom Ticket 19 failed 3 attempts even after the A1/T1 fixes.

Root cause My ticket body asserted an upper bound on a started_at >= sum — mathematically impossible — and the test was redundant with ticket 18's boundary test anyway. The agent thrashed against an unsatisfiable spec.

Fix Closed as spec bug with the reason recorded. Rule added to the skill: hand-solve a ticket on one line before queueing it; if the spec has no passing solution, no tier can find one.

Distilled lessons

  1. Judge artifacts, not self-reports. The diff and the gates decide; finish() is marketing.
  2. Test the gates against adversarial examples. PR #37 (zero tests, binary junk, green CI) is the template: every gate needs a change that must trip it.
  3. Context window ≠ cumulative tokens. Budget the per-request context in a chat loop.
  4. Tool design shapes behavior. No append tool → endless exploration. Fix the tool before blaming the model.
  5. The ticket body is part of the system. Hand-solve before queueing; name the seam; forbid the trap; size to the tier.
  6. Dual-OS CI from day one. Windows-only dev loops ship Linux-broken code.
  7. Status changes require a clickable truth. No pr_open without a URL a human can open.
  8. Pin what you execute. A batch must prove it runs current code (origin/main + marker grep).
  9. Fail the attempt, not the ticket. Junk/binary diffs retry; only spec bugs close.
